# hand-drawn-explainer

把一个概念、一份知识稿或一份现成文稿，做成**手绘风格的讲解视频**：配音、字幕、插画、线稿程序动画，一路到能直接发布的 MP4。

这是一个 **agent skill** —— 给 Claude Code、Codex 这类会写代码的 AI 助手用的一套流程规范 + 工具脚本，不是给人直接敲的 CLI。你对 agent 说"把这份稿子做成视频"，它照着 `SKILL.md` 一步步走；`lib/` 下的脚本是它手里的工具。

## 产出什么

一集成片 = 1920×1080 / 30fps / H.264 + AAC，外加 `.srt` 字幕、封面、章节时间戳，以及一份可逐条勾选的审稿包。画面由两层构成：

- **插画层**：生图模型出的分镜图（也可以完全不用生图，见下）
- **程序层**：手绘墨线风格的图形动画，用 [rough.js](https://roughjs.com/) 画线、[GSAP](https://gsap.com/) 驱动时间轴，逐笔展开

## 五个阶段，四个关口

| 阶段 | 做什么 | 关口 |
|---|---|---|
| 0 入口 | 判输入类型、选预设、估成本 | 四问答案 |
| 1 补底 | 概念或现成文稿 → 知识底座稿 | ① 确认底座稿 |
| 2 脚本 | 分镜、旁白、屏幕文字、红线扫 | ② 逐集确认 |
| 3 制作 | 配音 → 插画 → 程序动画 → 自查 | ③ 第 1 集样片 |
| 4 交付 | 渲染 → 终审 → 交付件 → 复盘回填 | ④ 全集 |

关口是硬的：没过就不往下派活；关口之间不再打断你。

## 三条贯穿始终的规矩

这三条是整套流程真正的骨架，不是风格偏好：

1. **时间只来自真实音频。** 镜头起止、字幕、每个动画事件的时刻，全部由配音的词级时间戳生成。脚本里写的时间段只是估算，从不进入成片。
2. **屏幕上的每个字都来自脚本的「屏幕文字」栏，一字不差。** 生图模型不写任何字；文字、圈框、箭头、问号全部由程序层叠加。这样改一个字不用重出图。
3. **改词只重做那一镜。** 动画事件挂在旁白短语上而不是帧号上，所以改哪一镜就只重合成哪一镜，时间轴自动重算。

## 不需要生图也能出片

`series.json` 里写 `"illus_mode": "svg"`，插画镜就改成由程序层直接画场景，**整条链一张生图都不需要**。适合线稿风格和有固定角色的系列；需要质感或复杂构图的画面仍建议走生图。

实测一条 58 秒的短片：脚本到成片约 40 分钟，其中机器时间只占 2 分钟（配音 1 分钟、构建 20 秒、渲染 32 秒），其余全是设计画面和看图判断。**这套流程的瓶颈从来不是算力。**

## 前置条件

```bash
zsh lib/doctor.sh      # 一次性检查全部依赖，缺什么会直说
```

需要：FFmpeg（**必须带 libass**，否则烧不了字幕）、Node（`npx` 拉 HyperFrames）、Google Chrome（无头截图自查）、Python 3 + Pillow + NumPy、中文字体、一个 TTS 服务的密钥。生图模型是可选的。

`lib/synthesize.py` 当前对接火山引擎 TTS，换别的服务改这一个文件即可——它对外只需要产出「每镜一个 mp3 + 一份词级时间戳 JSON」。

## 目录

```
SKILL.md          入口：五阶段、跨阶段铁律、工具一览
references/       每个阶段的作业规范（agent 按需读）
lib/              工具脚本：脚手架、配音、构建、量化自查、交付件
profiles/         预设：把受众口径、角色、画风、音色、目录约定打成一包
templates/        脚本与交付件模板
evals/            回归测试
vendor/           handraw-style：268 种手绘风格的提示词库（可选，参考图按需拉）
```

## 预设（profiles）

内核对任何主题、受众、画风都成立；把「受众是谁、有什么红线、用哪个音色、角色长什么样、成片放哪」这些打包成一个预设，跨集跨系列复用。

从 [`profiles/_template.md`](profiles/_template.md) 开始写自己的；[`profiles/example-xiaohei/`](profiles/example-xiaohei) 是一个能跑通的最小示例。

仓库**不带任何样例镜头库**——那是你用自己已交付的作品一集集攒起来的。

## 可选：268 种编号手绘风格

`vendor/handraw-style/` 带着一套编号风格库（风格名、参考作者、特征描述），想要比内置线稿更强的辨识度时可以挑一个编号，拼成生图前缀。仓库里只有**风格定义**（约 1 MB）；334 张参考图按需拉：

```bash
zsh vendor/handraw-style/fetch-images.sh
```

约 23 MB，只拉一次，拉完会校验编号与风格表是否对得上。不用编号风格就完全不必拉。

## 跑回归

```bash
zsh evals/smoke.sh
```

12 项，涵盖构建管道、文档与脚本的一致性、解析器行为锁、路径健壮性。其中前两项是「字节级对账」，需要你自己已交付过的一套真实产物当 oracle，不配就自动跳过：

```bash
export HDE_ORACLE_SERIES=/path/to/你的系列工程目录
export HDE_ORACLE_SCRIPTS=/path/to/你的脚本目录
```

## 这套流程不做什么

- 不做写实数字人、不做真人出镜
- 不替你判断内容对不对：事实以你给的知识稿为准，脚本与它的差异会被记成待回写清单，但不会自动改
- 不保证生图模型每次都画对：插画要人验收，不合格的重出那一张
- 逐笔「边讲边画」不在本仓库范围内，见 [`references/stroke-route.md`](references/stroke-route.md)
