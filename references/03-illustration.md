# 阶段 3 · 插画：画风自选、生图工具自选、放回即用

脚手架已经生成 `第N集/illus/生图提示词.md`（自包含：共用要求 + 每张的 LEFT/RIGHT 描述 + 文件名）和 `rows.json`。本文档只管三件事：选画风、选出图路径、验收放回。

## 1. 画风（阶段 0 已定，写在 `series.json` 的 `style`，全片统一；这里只说每种怎么用）
| style 值 | 适合 | 提示词前缀从哪来 |
|---|---|---|
| `line`（通用版缺省） | 任何题材的中性线稿 | 内置：白纸底、稀疏抖线、大留白、少量点色，无固定角色 |
| `xiaohei` | 方法、观点、抽象系统、隐喻（黑色小生物主体的开源视觉语言） | 内置：白底稀疏黑线、黑色小生物主体、少量红橙蓝点色；固定角色由预设定义 |
| `q-human` | 传记、历史、真实人物 | 内置：自然肤色 3–4 头身 Q 版、干净轮廓、有限平涂（`stroke-route.md` 指向的 nikola 有更细的人物锚点） |
| `handraw:<编号>` | 想要辨识度更强的任何手绘风 | `$HDE/vendor/handraw-style/`：268 种编号风格（**参考图按需拉**，见下） |

**挑 handraw 编号**（属阶段 0 四问）：仓库只带风格定义不带参考图，第一次用先拉一次（约 23 MB，334 张，之后不用再拉）：

```bash
zsh $HDE/vendor/handraw-style/fetch-images.sh
```

拉完让用户打开画廊 `$HDE/vendor/handraw-style/handdraw-style-prompter/gallery/index.html` 记下编号；或按分组给他三个候选（A 社论漫画 / B 绘本 / C 平面人物 / D 日本 / E 中国 / F 通用网感 / G 中国补充 / H 其他）。选定后从 `handdraw-style-prompter/references/styles.json` 取该编号的 `reference`（参考作者 / 风格名）、`generation_name`、`traits`（只取正向特征，去掉含"避免 / 不要"的句子），拼成前缀：`风格名称：#编号 · 风格名。参考作者/风格名称：…。核心风格特征：…`，英文同款。生图模型认不出风格名时再附 `images/individual/<段>/<编号>.webp`（或同目录 `<编号>_grid.webp`）作为**只借画风**的参考图，并加一句"只提取线条、笔触、媒介、色彩倾向，不沿用参考图任何主体、构图、文字"。
换画风只换前缀与参考图；角色设定、构图约束、无字约束不变。

## 2. 共用约束（脚手架写死在每份生图提示词里，别删）
16:9；左上角与右上角留空（Logo / 集数条位）；底部留空给字幕条（数值以 03-production §3 安全区为准，约 18%）；左右两岛中间留约 8% 空沟、不跨沟连线；**绝对不出现任何文字、字母、数字、伪字、Logo、水印，不画圈框、箭头、问号、感叹号**；纸张、卡片、屏幕上只画简单线条。描述里"写字"改成"笔尖落在纸上"。有固定角色的，角色设定原样附在共用要求里，并给一张 `assets/ref-style.png` 当角色与画风参考。

## 3. 出图路径（阶段 0 已定，记在 `_chain/plan.md` 与 `series.json` 的 `illus_mode`；这里未定才回阶段 0 补问，不在本阶段另起追问）

### 路径 0（可选，不默认）：代码画场景，不依赖任何生图
`series.json` 写 `"illus_mode": "svg"`（或 scaffold 加 `--illus-mode svg`）。插画镜变成 `scene` 镜：脚手架在 shots.json 里给 `left / right`（单幅 `main`）事件，并生成 `illus/场景说明.md`，写 episode.js 时先把每个场景的四行填掉再动手：
1. **画布分区**：左右两岛（中间留 8% 沟）或单幅；每岛的包围盒。
2. **大块区域与遮挡顺序**：地面 / 墙 / 桌面这类大块先画，从后到前列出。
3. **对象清单（从大到小）**：人物、道具、环境件各一行，写清位置锚点（中心、底边）与尺寸；同一个对象跨镜复用同一参数。
4. **共用坐标**：相邻对象应该贴合的边用同一个数（桌面 y = 人物脚底 y）。
画法：全部用 core.js 的 rough 图形与角色 helper，`sc.draw` 按对象清单顺序逐件画出，事件对齐旁白；表情、手势用最少的线（一条弧线的嘴、两点眼），做不出来的姿态换成道具或位置关系来表意。适合线稿风与固定角色；不适合 handraw 编号风格与需要质感的画面。同一集可与生图混用：复杂场景那几镜仍走下面的路径。
自审：`shot_metrics.py` 照常量；场景里元素个数不超过 12，超过就是画得太满。常用姿态与场景件沉淀进 [03-shot-patterns.md](03-shot-patterns.md)「场景与姿态」节。

### 路径 1–3：生图模型
| 路径 | 怎么做 | 注意 |
|---|---|---|
| **Codex image_gen** | `codex exec --skip-git-repo-check -s workspace-write --add-dir ~/.codex -C <项目根> "$(cat 第N集/illus/生图提示词.md 的 Codex 版任务)" < /dev/null`，后台用 `nohup … &` | 必须 `< /dev/null`，否则卡在读 stdin；单张约 4 分钟；账号有额度上限，撞上就是硬阻塞（脚手架的提示词本来就自包含，随时能换路径） |
| **网页生图** | 把 `生图提示词.md` 的共用要求 + 单张描述贴进任何生图网页；下载名统一 `<前缀>_<集>_<镜>.png`，`zsh $HDE/lib/move_dl.sh <项目根> <前缀>` 归位 | 每张都要附参考图；手工量大时先出第 1 集验风格 |
| **其他 API** | 用户自接；产物按 `第N集/illus/NN.png` 放回即可 | 尺寸 ≥1920 宽，16:9 |

Codex 版任务头部固定四句：先用 view_image 看 `assets/ref-style.png` 作为画风与角色参考；用内置 image_gen 按顺序逐张生成；每张生成后立即从 `$CODEX_HOME/generated_images/` 复制到指定路径（已存在的跳过）；遇到额度或频率限制立即停止并回复 LIMIT 与已完成清单。

## 4. 验收与放回
每张看一眼：角色（若有）跨图一致、没有伪字与标注、四角与底部留位到位、左右岛不串。不合格的只重出那一张。放回后：
```bash
python3 $HDE/lib/build.py 第N集     # 重新复制到 comp/assets
```
再按 `03-production.md` §5 调 `marks.json` 的 `split`。

## 5. 降级
生图路径不可用时，程序动画照做，进度表记「插画 ❌ 缺 N 张」；**不默认渲无插画成片**，只有用户明确要先看时才渲 `render/第N集_v0-无插画.mp4`，且它只留工程区，绝不进交付区；插画补齐后重跑 build 与渲染才算最终版。
