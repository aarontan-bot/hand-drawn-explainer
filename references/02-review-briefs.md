# 三路审稿派工

**管这一段**：全部脚本写完、机器扫干净后，派三路 agent 各出一份问题清单；产出三份清单，交回主循环统改（02-script 第 5–6 步）。

全部脚本写完后一次性并行派出。三路都必须自己读真相源原文和全部脚本，不许只读摘要；互不通气，各自独立出问题清单；主循环统改。派工时把下面的尖括号替换成绝对路径。

## 第一路｜真相源对账与事实核对（deep-reasoner）

> 读 <真相源绝对路径> 和 <脚本目录> 下全部脚本。逐条做四件事，只报问题，不改稿：
> 1. **对账**：真相源每节的每条要点、每个例子、每个"一句话记住"，是否都落到了某个镜号？列出遗漏项与节号。
> 2. **原文一致**：脚本里的数字、例子文字、术语说法与真相源逐字比对，列出所有不一致（含被写顺手改掉的措辞）。
> 3. **数字写死**：找出点了具体型号、尺寸上限、Token 数、版本号的地方；<spec 绝对路径> 稳定数字白名单里的除外。
> 4. **来源泄漏**：找出旁白和屏幕文字里出现的原作者、论文题目、原课程名、厂商名，以及"原材料提到"这类编写过程措辞。
>
> 输出 `集号 / 镜号 / 问题类型 / 原文摘录 / 建议`。

## 第二路｜受众视角（deep-reasoner）

> 你是 <受众描述，来自 spec>，自己一个人看这套视频，没人讲解。读 <脚本目录> 下全部脚本，按镜顺序逐集看下来，回答：
> 1. 哪一镜开始听不懂？具体是哪个词、哪句话跨度太大？
> 2. 哪一段会让你想跳过（太长、太像上课、重复、没有故事）？
> 3. **脊柱检查**：把每集各节的顺序打乱，你会察觉吗？能随意换序的集就是没有主线，指出来。
> 4. 抽象概念有没有先落到你身边的具体场景，还是直接念定义？逐个概念判断。
> 5. 互动题（若有）你答得上来吗？停顿够不够？
> 6. 哪些术语过难，或者中文说法比原文还费解？
>
> 只报问题和你的真实反应，不改稿，不客气。输出 `集号 / 镜号 / 你的反应 / 建议`。

## 第三路｜规则与风格审（通用版：general-purpose；预设可指定为守门人 agent）

> 对照 <全片设定绝对路径>、<spec 绝对路径> 的「判断规则」与「验收标准」、`$HDE/references/02-script.md` 的硬规则与写作原则，审 <脚本目录> 下全部脚本。逐条查：每镜是否写出主图与做法、颜色两层是否守住、先总览后细节、推导过程有没有画出来、每种方法有没有配自己的例子、屏幕文字是否少而准、插画有没有被要求画字或标注、画面会不会长时间静止、口吻是否顺嘴、例子是否贴近受众、预设红线（若有）。
> 只报问题并注明违反哪一条，不拍板、不改稿。

## 统改时
- 三路冲突由主循环裁决，裁决理由写进 spec「统改裁决」段。
- 第二轮审稿要把第一轮已修清单注入 prompt，避免重复报。
- 统改完对 spec 验收清单逐条对账并给出结果，不是口头"改完了"。
