# 阶段 0 · 入口：判输入、选预设、四问、估成本、落链

## 1. 判输入类型（一句话判定）
- **概念**：用户只给了主题或一句话（"讲一下向量数据库""做一条讲光合作用的"）→ 走阶段 1 补底。
- **知识稿**：已有一份按知识点组织、带例子和术语的稿（课程模块稿、教案、讲义）→ 跳过阶段 1，它就是知识真相源。
- **现成文稿**：文章、视频转录、别人的脚本，观点事实水分混在一起 → 走阶段 1 的「内容梳理与核验」分支。

## 2. 选预设
列出 `$HDE/profiles/` 下除 `_template.md` 外的文件名问用户；不选就是通用版。选定后**先读完预设**再问四问：预设可能已经替用户答了"受众口径 / 角色画风 / 音色 / 目录"。把选定的预设名写进 `series.json` 的 `profile` 字段。

## 3. 四问（有分量的任务必问；用户说"直接做"或同口径续作可跳）
| 问 | 为什么 | 缺省建议 |
|---|---|---|
| **交付边界**：只出脚本 / 脚本 + 第 1 集样片 / 全集成片 | 画风没验过就做全集必返工 | 只出脚本，逐集确认后再制作 |
| **集数与时长档位**：单集短片几分钟；系列几集、每集几分钟 | 决定字数、镜头数、插画张数、子代理数、成本 | 系列每集 5–7 分钟；一集只讲透一件事，不轻易合并 |
| **受众与口径**：讲给谁听、几岁、有没有红线（预设通常已答） | 决定"可感尺度"、术语处理、互动题、审稿视角 | 按预设；通用版按用户描述 |
| **角色 / 画风 / 音色 / 出图路径**：有没有固定角色；画风（`line` 中性线稿 / `xiaohei` / `q-human` / `handraw:<编号>`，见 03-illustration §1；选 handraw 时让用户打开画廊记编号）；TTS 音色 id；插画走哪条出图路径（生图模型三选或代码画场景） | 跨集统一才有系列感；这四项在这里一次收口，阶段 3 不再问 | 按预设；通用版缺省无固定角色、画风 `line`、**音色必问**（内核不带缺省音色）、出图路径必问 |

## 4. 时长档位与成本预估（回答四问时一并报给用户）
按语速 300 字/分钟估算，实测成片密度约 280–290 字/分钟（含画面停留与停顿）。

| 每集时长 | 旁白字数 | 镜头数 | 插画镜（约每 3–4 镜一张） | 程序镜 | 制作子代理 |
|---|---|---|---|---|---|
| 2–3 分钟 | 600–900 | 10–16 | 3–5 | 6–11 | 1 |
| 4–6 分钟 | 1200–1800 | 16–26 | 5–8 | 10–18 | 1 |
| 7–10 分钟 | 2100–3000 | 26–36 | 8–12 | 16–24 | 1–2 |

报给用户的成本四行：**配音字数**（按字计费的 TTS 直接乘单价）、**插画张数**（Codex image_gen 单张约 4 分钟且有账号额度上限；网页生图按张手工）、**程序动画**（每集一个子代理约 30–40 分钟并行）、**渲染**（1080p 每分钟成片约 3–6 分钟机器时间，`doctor.sh` 会给本机实测值；长片临时空间可达数十 GB，先 `df -h`）。

## 5. 落 `_chain/`
四问确认后按 intent-chain 规则在项目根写 intent / spec / plan（spec 里必含：受众口径、角色与画风、稳定数字白名单、验收清单）。`series.json` 同步写好：

```json
{"title": "", "speaker": "<必填>", "style": "line", "illus_mode": "image", "characters": "", "profile": ""}
```

## 完成判据
- 输入类型、预设、交付范围三项都有明确答案并写进 `_chain/intent.md`。
- 四问的答案与成本四行已贴给用户并得到回复。
- `series.json` 与 `_chain/` 三件套存在；只做某一阶段的任务可只更新 plan。
